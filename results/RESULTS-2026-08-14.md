# Results — 2026-08-14

Dated snapshot of published and live measurements for this recipe.
The [README](../README.md) keeps the short “what to expect” table; this file
holds the full tables, method notes, and historical lanes.

> **Dated snapshot (2026-08-14).** The lane has since moved to the
> Vision-Exp checkpoint (`deepseek-v4-flash-vision-exp`, MTP_NUM_TOKENS=6);
> commands below naming `deepseek-v4-flash-0731` describe the 0731 lane as
> measured that day — substitute the served name for the current lane.

**Default stack as of 2026-08-14:** Anemll `ghcr.io/anemll/dspark-vllm-gx10:0.1.1`,
official `deepseek-ai/DeepSeek-V4-Flash-0731` @ `9e165c30…`, TP=2,
`max_model_len=1048576`, `max_num_seqs=6`, `nvfp4_ds_mla`, MTP-5.

How to read the numbers:

| Phrase | What it actually is |
| --- | --- |
| “1M context” | Server **ceiling**. Any one chat *may* grow to 1M. Not six chats already holding 1M. |
| Aggregate tok/s | Fleet generation (all streams together). ~160–190 at c=6 is **six short chats decoding**. |
| Per-stream tok/s | What one concurrent chat feels like after the first token. |
| 6 × 128K collapse | Six **cold huge prefills**. After issue #27 they run **one at a time**; wall clock is almost all prefill. |

Same server as the default recipe (`:8888`, issue #27 + #43 applied).
Unique cold prefixes, `thinking=false`, `max_tokens=min_tokens=128`,
`ignore_eos`. Cell value = median per-stream decode tok/s after first token.

Raw JSON: [`bench-screenshot-matrix-20260814.json`](bench-screenshot-matrix-20260814.json).

| Prompt | c=1 | c=2 | c=4 | c=6 | c=6 aggregate |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 256 | 82.6 | 56.9 | 54.3 | 35.9 | 162 |
| 2,048 | 64.6 | 50.1 | 29.6 | 20.8 | 78 |

| 32,768 | 62.0 | 39.7 | 8.7 | 8.2 | 8 |
| 131,072 | 74.9 | 36.0 | 8.4 | 8.6 | 2 |

- **c=1 is flat** (~62–83 tok/s) from 256 through 128K. Solo decode is fine.
- **c=6 short prompts** still land in the ~160–190 aggregate band (256 → **162**).
- **c=4/6 × 32K+** sit on the ~8 tok/s mixed-prefill floor (one decode token per
  serialized prefill step). 128K × c=6 median TTFT was **282 s**.
- This is **not** a c=1 regression vs 1 Aug (128K TTFT 80.4 s vs 78.8 s).

This table is **not** what `scripts/benchmark-0731.py` prints. That script
uses natural ~512-token completions and does not force `thinking=false`.
With `DEFAULT_THINKING=max` it will spend the window in `<think>` unless
you cap `max_tokens` or disable thinking. Use it to rematch the 1 Aug sweep in the next section.

```bash
python3 scripts/benchmark-0731.py \
  --base-url http://127.0.0.1:8888/v1 \
  --model deepseek-v4-flash-0731 \
  --output results/deepseek-v4-flash-0731.json
```

## 2026-06-29 — 1M / 6 aggregate microbench (~182 tok/s)

This is the “~170–182 tok/s with 6 concurrent **and** 1M context” number.
`max_model_len=1048576`, `max_num_seqs=6`, NVFP4, Keys mask on that deployment.
Code-completion microbench: **6/6**, **~182 tok/s aggregate** (~30/stream).
Solo code decode ~67 tok/s. KV pool then ~1.90M tokens (~1.81× at full 1M).

Typical agent turns sit far below 1M, so six sessions share the pool while the
1M ceiling stays available. This is **not** six simultaneous full-1M (or even
six cold 128K) prefills.
